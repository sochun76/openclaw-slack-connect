# 페르소나 자료를 OpenClaw 파일로 나누는 법

사용자가 주는 자료는 셋 중 하나다.

1. **표준 파일**(IDENTITY.md, SOUL.md, USER.md, AGENTS.md, MEMORY.md): 내용을 읽고 보여 준 뒤 `persona.py apply`.
2. **채용설계서**(AX COACHING 워크북 등 9단계 문서) 또는 자유 형식 문서: 아래 표대로 나눠 임시 폴더에 쓰고, 사람에게 요약을 보여 확인받은 뒤 `persona.py apply --from <임시 폴더>`.
3. **아무것도 없음**: 인터뷰로 만든다(아래 "인터뷰 순서").

## 채용설계서 → 파일

| 설계서 항목 | 파일 |
|---|---|
| 이름, 직책/소속, 한 줄 소개 | IDENTITY.md (`- **Name:**`, `- **Creature:**`, `- **Vibe:**` 줄 + 소개 문단) |
| 채용 목적(미션), 성격과 행동 원칙, 상사 의견에 문제가 있을 때, 우선 가치, 하지 않아야 할 일(경계), 말투 | SOUL.md |
| 주요 사용자, 상사/최종 판단자, 호칭, 말투 선호, 우선순위 | USER.md (지시문 형식, 아래 참고) |
| 핵심 역할, 주요 업무와 완료 기준, 전결권(스스로/처리 후 보고/승인 후), 도구와 접근 범위, 협업자와 요청 범위, 보고(즉시/정기/알림 조건), 채널별 행동 | AGENTS.md |
| 장기간 기억할 사실과 결정, 연결할 회사 자료 위치 | MEMORY.md |

USER.md 지시문 형식(OpenClaw 템플릿 규칙):
```md
<!-- observed: YYYY-MM-DD | status: active -->

- Always address the user as "...".
```

## 꼭 지킬 것

- **기존 내용 보존:** 적용 전 `persona.py backup`. 에이전트가 스스로 적어 둔 기록(USER.md의 지시문 등)은 지우지 말고, 바뀌면 이전 것을 `status: superseded`로 표시한다.
- **임의로 채우지 않는다:** 미작성 항목, 서로 맞지 않는 내용(예: 보고 시각이 두 개, 승인자가 둘), 예제 문구를 그대로 둔 것으로 보이는 항목은 사용자에게 묻는다. 워크북 예제("김대표", "인테리어 회사", "사내 공유폴더/공무팀" 등)를 사실로 쓰지 않는다.
- **비밀은 넣지 않는다:** 비밀번호, API 키, 토큰.
- **여러 사람이 쓸 에이전트:** MEMORY.md와 USER.md는 모든 대화에 읽힌다. 직원·외부인이 보면 안 되는 내용은 넣지 않는다.
- **외부 공간용 에이전트:** 회사 고유 정보(직원 이름, 메일, 내부 절차)를 빼고 일반 규칙으로 쓴다.
- 파일 언어는 사용자가 고른 언어로 쓴다. 섞어 써도 되지만 한 파일 안에서는 한 언어를 기본으로 한다.

## 인터뷰 순서 (자료가 없을 때, 한 번에 하나씩)

1. 미션: 왜 있나? 동사와 결과가 있는 한 줄
2. 성격: 형용사가 아니라 행동으로 3~5개
3. 경계: "하면 안 되는 것" 3개 이상
4. 말투: ✅/❌ 예시와 호칭, 답변 길이
5. 이름(한글/영문)과 한 줄 소개
6. 상사·사용자, 협업자, 보고 대상
